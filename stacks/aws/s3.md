## What it is

Amazon S3 is AWS's object storage service — durable, eleven-nines, the de-facto data lake substrate. Storage classes range from Standard (hot) through Glacier Deep Archive (cold, hours-to-restore). Tightly integrated with KMS, IAM, CloudFront, Athena, Redshift, OpenSearch, and SageMaker.

Canonical surface: [docs.aws.amazon.com/s3](https://docs.aws.amazon.com/s3/).

## When to use

| Need | Use S3? |
|---|---|
| Object storage (files, blobs, backups) | Yes — the default |
| Data lake (Parquet, JSON, Avro) | Yes — usually with S3 Tables (Iceberg) |
| Static website / CDN origin | Yes — S3 + CloudFront |
| Database storage | No — use [RDS](/stacks/aws/rds/) / [Aurora](/stacks/aws/aurora/) / [DynamoDB](/stacks/aws/dynamodb/) |
| Long-term archival | Yes — S3 Glacier storage classes via the S3 API |
| Single-AZ low-latency object I/O | Yes — S3 Express One Zone |

## 2025-2026 currency anchors

- **S3 Tables** (re:Invent 2024) — fully managed Apache Iceberg tables on S3. AWS handles compaction, snapshot management, time-travel. Default lakehouse table format on AWS.
- **S3 Express One Zone** — single-AZ, sub-ms object storage for high-frequency reads. **Conditional writes/deletes** added 2025-2026: `If-Match`, `If-None-Match`, `x-amz-if-match-last-modified-time`, `x-amz-if-match-size`.
- **Glacier vault APIs (`glacier:*`)** are on retirement track. Use S3 Glacier storage classes (Instant Retrieval, Flexible Retrieval, Deep Archive) via the S3 API — `PutObject` with the right `StorageClass`.
- **Block Public Access at account level** is the assumed default; only explicit per-bucket exceptions.
- **S3 Intelligent-Tiering** is the recommended default for unpredictable access — no retrieval cost surprises.
- **Zero-ETL from S3 to OpenSearch / Redshift** matured 2024-2025.

## Patterns

### Storage class selection

| Class | Access pattern | Cost shape |
|---|---|---|
| **Standard** | Frequent reads | High storage, no retrieval cost |
| **Intelligent-Tiering** | Unpredictable | Auto-tiers between Frequent + Infrequent + Archive tiers |
| **Standard-IA / One Zone-IA** | Infrequent, known | Lower storage, retrieval cost |
| **Express One Zone** | High-frequency low-latency single-AZ | Highest storage cost, lowest latency |
| **Glacier Instant Retrieval** | Quarterly access, milliseconds | Cheap storage, retrieval cost |
| **Glacier Flexible Retrieval** | Once-a-year access, minutes-hours | Cheaper storage |
| **Glacier Deep Archive** | Compliance, years-of-retention | Cheapest storage, 12h retrieval |

Default for new buckets: Intelligent-Tiering. Lifecycle policy to move to Glacier classes at known thresholds (e.g., 90 days untouched → Glacier Instant, 365 days → Deep Archive).

### S3 Tables (Apache Iceberg)

```sql
-- Create an Iceberg table in S3 Tables
CREATE TABLE my_namespace.orders (
  order_id STRING,
  customer_id STRING,
  total DECIMAL(10,2),
  created_at TIMESTAMP
) USING iceberg
TBLPROPERTIES ('format-version'='2');

-- Time-travel
SELECT * FROM my_namespace.orders FOR VERSION AS OF 1234567890;
```

Schema evolution: add columns, rename, reorder without rewriting data. Query from [Athena](/stacks/aws/glue/), Redshift Spectrum, EMR, Glue Catalog. **S3 Tables auto-compacts**; raw Athena+Glue + S3 Parquet does not.

### Encryption

- **Default SSE-S3** is not enough for most compliance. Use **SSE-KMS** with a customer-managed key (CMK) for production buckets containing sensitive data.
- **Account-level Block Public Access** on; per-bucket exceptions documented.
- **Bucket policy** enforces `aws:kms` SSE for `PutObject` if compliance requires it. See [`/stacks/aws/security-engineer/`](/stacks/aws/security-engineer/) for the RCP pattern.

### Conditional writes (S3 Express One Zone, 2025-2026)

```bash
# Atomic compare-and-swap — write only if ETag matches expected
aws s3api put-object \
  --bucket my-bucket \
  --key my-key \
  --body file.json \
  --if-match "abc123"
```

Use for optimistic concurrency on shared object state (config files, lock files). Removes need for DynamoDB as a coordination layer for simple write-once-if-not-exists patterns.

### Access from VPC

- **Gateway endpoint** for S3 — free, route-table-based. Default for any VPC with private subnets accessing S3.
- **Interface endpoint (PrivateLink)** for S3 — paid, but supports cross-VPC, on-prem, and access-policy granularity. Use for sensitive workloads.

### Object Lock for compliance

```json
{
  "ObjectLockEnabled": "Enabled",
  "Rule": {
    "DefaultRetention": {
      "Mode": "COMPLIANCE",
      "Days": 2555
    }
  }
}
```

- **Governance Mode**: admins can override.
- **Compliance Mode**: no one (including root) can delete during retention period.

Use for audit logs, financial records, regulatory archive. Pair with KMS for encryption-at-rest.

### Lifecycle policies

```yaml
Rules:
  - Id: ArchiveOldData
    Status: Enabled
    Transitions:
      - Days: 90
        StorageClass: GLACIER_IR
      - Days: 365
        StorageClass: DEEP_ARCHIVE
    Expiration:
      Days: 2555  # 7 years
```

Always set lifecycle policies on production buckets — uncontrolled growth is a budget killer.

## Anti-patterns

- **Public S3 bucket** without explicit business need and explicit security review. Block Public Access at account level.
- **`glacier:UploadArchive`** for new code. Use S3 Glacier storage classes via the S3 API.
- **No SSE-KMS** for sensitive data. SSE-S3 is the bare minimum.
- **No lifecycle policy** on buckets. Storage costs grow without bound.
- **No versioning** on critical buckets. Accidental deletes / overwrites are unrecoverable.
- **Cross-region replication without KMS multi-region keys.** Replication breaks across regional KMS boundaries.
- **`s3:*` IAM permissions.** Scope by bucket + prefix at minimum.
- **Lambda → S3 → Lambda fan-out** without considering 6 MB payload limit. Drop large payloads to S3, pass a reference.

## Gotchas

- **S3 PUT/GET request rate quotas** — 3,500 PUT/COPY/POST/DELETE and 5,500 GET/HEAD per partitioned prefix per second. Hot prefix = throttling. Distribute keys with high-cardinality prefixes.
- **S3 Standard 99.999999999% (11 nines) durability** is across multiple AZs. **S3 One Zone-IA** and **Express One Zone** are single-AZ — AZ failure = data loss.
- **S3 list operations** are eventually consistent for some object versions; use Inventory reports for accurate listing at scale.
- **Cross-region replication latency** is typically seconds-to-minutes; not synchronous.
- **CloudTrail data events for S3** are expensive at scale (per-object API call cost). Enable selectively or use Lake.
- **Bucket name uniqueness** is global — and bucket names appear in URLs.
