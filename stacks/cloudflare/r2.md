## What it is

R2 is Cloudflare's object storage — S3-compatible API with **zero egress fees**. Native R2 binding from Workers (`env.R2.get/put/list/delete`) is faster than the S3 API. R2 SQL lets you query Parquet/CSV files in place. Event notifications can trigger Workers on object operations.

Authoritative reference: [developers.cloudflare.com/r2](https://developers.cloudflare.com/r2/).

## When to use

- **Large media library, user uploads, log archives** — any large-blob workload where egress matters.
- **Static asset hosting** behind a Worker or [Workers Static Assets](/stacks/cloudflare/workers-static-assets/).
- **Analytics data lake** — Parquet files queried in place with R2 SQL.
- **Backups** — D1 exports, application backups, immutable audit logs (with object lock).

Don't use R2 when:

- **Small frequently-mutated objects** — [KV](/stacks/cloudflare/kv/) is cheaper and faster for that shape.
- **Transactional data** — R2 is eventually consistent on metadata operations; use [D1](/stacks/cloudflare/d1/) or [DO](/stacks/cloudflare/durable-objects/).
- **Operational queries that need low-latency response** — use Analytics Engine for online metrics, R2 SQL only for ad-hoc offline analytics.

## 2025-2026 currency anchors

- **Zero egress fees** is R2's killer property. If you serve 100TB/mo to users out of S3, that's ~$9000 in egress; out of R2, $0.
- **R2 SQL** — query Parquet/CSV in R2 with SQL, no Athena/Snowflake spin-up needed.
- **Event notifications** — bucket operations trigger Workers; useful for pipeline orchestration.
- **R2 location hints** — bucket-level placement (`auto`, `EU`, `ENAM`, FedRAMP regions on relevant plans).
- **"S3-compatible" has gaps** — some less-common S3 operations are not implemented. Stick to the documented S3 surface ([R2 S3 API compatibility](https://developers.cloudflare.com/r2/api/s3/api/)).

## Patterns

### Bucket layout for multi-tenant

```
my-bucket/
├── tenant-1/uploads/...
├── tenant-1/exports/...
├── tenant-2/uploads/...
└── public/static/...
```

Tenants prefixed in keys, IAM scoped at the bucket level. For stronger isolation: one bucket per tenant (cost: bucket count adds up at large tenant count).

### Signed URLs for direct upload/download

```ts
const url = await env.R2.createPresignedUrl({
  bucket: "user-uploads",
  key: `tenant-${tenantId}/${userId}/${crypto.randomUUID()}`,
  method: "PUT",
  expiresIn: 3600
});
return Response.json({ url });
```

Direct browser → R2 upload, skip the Worker for the bytes. Workers stay cheap; R2 handles the upload.

### Native R2 binding (preferred from Workers)

```toml
[[r2_buckets]]
binding = "ASSETS"
bucket_name = "prod-assets"
```

```ts
// Read
const obj = await env.ASSETS.get("path/to/key");
const text = await obj?.text();

// Write
await env.ASSETS.put("path/to/key", body, {
  httpMetadata: { contentType: "application/json" },
  customMetadata: { tenant: "t1" }
});

// List
const list = await env.ASSETS.list({ prefix: "tenant-1/", limit: 100 });
```

Faster than S3 SDK, no signing, types-aware. Use this from Workers.

### S3 SDK for external clients

```ts
import { S3Client, GetObjectCommand } from "@aws-sdk/client-s3";

const s3 = new S3Client({
  region: "auto",
  endpoint: `https://${env.ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: { accessKeyId: env.R2_KEY, secretAccessKey: env.R2_SECRET }
});
```

Works for most S3 clients. Use this when you have an existing S3-shaped pipeline or external tooling.

### R2 SQL for ad-hoc analytics

```sql
SELECT user_id, COUNT(*) AS events
FROM 'r2://my-bucket/events/year=2026/month=05/'
WHERE event_type = 'click'
GROUP BY user_id
ORDER BY events DESC
LIMIT 100;
```

Cost is per-query (data scanned + compute). Suitable for ad-hoc analytics; not for high-QPS workloads.

### Pipelines → R2 for high-volume ingest

See [Pipelines](/stacks/cloudflare/pipelines/) — buffered HTTP ingest, written to R2 in Parquet/JSON, queryable via R2 SQL. The Cloudflare-native "fire-hose into analytics" path.

## Anti-patterns

- **Tiny-object KV-style usage in R2** — overhead per object; use KV for that shape.
- **Versioning disabled on critical buckets** — enable per-bucket; lifecycle rules for old versions.
- **Storing PII in R2 without lifecycle policies** — GDPR DSAR/deletion requires you can identify and delete tenant data.
- **Trusting `auto` region for compliance** — for HIPAA / data-residency, pick the right region hint (`EU`, `ENAM`, FedRAMP region) at bucket creation.

## Gotchas

1. **R2 is eventually consistent on metadata** for some operations (list-after-put visibility may take seconds).
2. **S3 compatibility gaps** — verify your client uses operations on the [supported list](https://developers.cloudflare.com/r2/api/s3/api/).
3. **Class A vs Class B operations** have different pricing — writes/lists are Class A; reads are Class B. Plan around access patterns.
4. **No built-in PITR** like D1 time-travel; versioning + lifecycle is the closest equivalent.
